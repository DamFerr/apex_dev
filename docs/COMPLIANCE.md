| 2 | No hidden information | Only data the League client already shows the player (champ select via LCU). No enemy cooldown or fog-of-war tracking. Other: the app reads champ select data from the local League client. It writes only your summoner spells in champ select (PATCH my-selection) and, when you click a suggestion button with the opt-in switch on, your own champ select action (PATCH actions/<id> with only championId, plus completed: true to lock in or ban; POST actions/<id>/complete as a one-time fallback) and rune pages named "Apex: <champion>" (explicit button, or opt-in auto-import which is off by default). The Rust command refuses any other endpoint and any method except GET/POST/PUT; it never touches your own pages. The overlay window is click-through: hover, right and middle clicks, the wheel and every click outside the card go to the game, and the cursor stays the game's. To let you move the card, a Windows mouse hook and a short polling loop read the left button state and the cursor position (nothing else, no keys), and a left press that starts on the card moves the overlay window; when the hook sees such a press it swallows it (and its release) so the game does not get it, and only there. No input is ever sent or injected into the game, no game state is read, and the overlay needs no global hotkey. It appears only while League's game window is the foreground window (Apex reads that window's class name only, nothing from the game) and only if you turned it on; it hides when you alt-tab away.


## Policy flags for later phases (read before building these; found in the Nov 2026 policy check, verify on the Developer Portal)
- **MMR / ELO estimates.** The plan lists "MMR band estimates" (PDF 4.1). The General Policy forbids alternatives to the official ranking system, including MMR or ELO calculators. Do not build an MMR estimate; use the official tier/division/LP only.
- **Power-spike alerts and item-spike indicators** (PDF 3.3 "power spike timelines", 3.7 overlay "item-spike indicators"). Third-party summaries of the League rules prohibit notifications that alert players when a power spike hits. Keep these out of the in-game overlay; analysis after the game is fine.
- **Ranked Solo/Duo champ select names.** Players' names must stay hidden in ranked champ select (visible again at loading screen). The Draft screen shows champions only, never names. Keep it that way for any new draft feature.
- **Queues.** The collector reads Ranked Solo only (queue 420). Brawl and League Classic data must not be aggregated or shown. Match history is an allow-list (Ranked Solo/Duo, Ranked Flex, Normal Draft, ARAM, Arena; `packages/schema/src/queues.ts`), including under "All".
- **Scouting and production key.** Live Game scouting and "smurf score" (P4) can weigh on the production key application; describe them accurately and review before applying.

- **Overlay v1 scope decision (Nov 2026).** The plan lists "next item" and "item-spike indicators" for the overlay (PDF 3.7). Not built: a next-item tracker needs your live inventory and gold (Live Client Data, planned P3) and reads close to a power-spike alert, which is on the list above. The overlay therefore stays a static build card. Before any live-data overlay feature (P3), re-check it against the policy and keep power-spike and cooldown-style cues out.
